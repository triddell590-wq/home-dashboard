# Calendar and Morning Reminders Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A synced Calendar tab where Tom types events in plain words, sees lesson days beside them, and gets one 7am London notification on days with something on, sent by a GitHub job with his Mac off.

**Architecture:** Pure modules under `js/calendar/` (parser, occurrences, records/actions, wording, digest) are shared by the page and by `tools/notify.mjs`, because Node imports the same ES modules. The page reads and writes only through `data()` and redraws from `watch`. Push uses the vendored Firebase Messaging compat library in the page only. `sw.js` stays a classic script and shows data-only pushes itself (Farm Ledger's pattern). A cron-job.org timer starts `.github/workflows/notify.yml` every hour, with GitHub's own schedule as a backup. The sender records `reminders/{date}`, so a day is never sent twice.

**Tech Stack:** Plain ES modules, no build step; Firestore + Messaging compat SDK 10.7.0 (vendored); the repo's own test harness (`js/tests/harness.js`); Node 20; `firebase-admin` (devDependency, tools only); GitHub Actions; cron-job.org (free, set up by Tom).

**Spec:** `docs/superpowers/specs/2026-11-23-calendar-design.md`. It builds on `docs/superpowers/plans/2026-11-23-lessons-weather-online.md`, which is merged before this plan runs. Treat everything that plan produces as existing: `registerSettingsCard`, the Overview card `watch`, `londonDay`/`londonHourStart` in `js/core/dom.js`, `addDays`/`weekdayIndex` in `js/lessons/sums.js`, `recordsFrom`/`watchLessons` in `js/lessons/records.js`, `refreshWarnings` in `tools/warnings.mjs`, `ownerUidFromRules` in `tests/rules/owner.mjs`, `firebase-admin` in devDependencies, and the browser check's CDP `Fetch` interception and seeding through `import("./js/core/data.js")`.

## Global Constraints

- £0. Plain ES modules with no build step. iOS Safari (home-screen app, iOS 16.4+) and desktop browsers. Test-first. Reduced motion is respected.
- Everything is in Europe/London. "Today" is `londonDay(now)`. Dates are `"YYYY-MM-DD"` strings and times are wall-clock `"HH:MM"` strings. Date arithmetic goes through `addDays`/`Date.UTC`, never local time. Every test uses fixed dates and an injected `today`/`now`; no test reads the real clock.
- The Firestore layout follows spec §2 exactly, under `users/{uid}/`:
  - `events/{id}` `{title, kind, date, time, repeat, until, skipped, done, note, createdAt, updatedAt}` (id from `crypto.randomUUID()`), with `repeat` = `null | {unit, every, monthly}` and `nth` added only when `monthly === "weekday"`.
  - `devices/{id}` `{token, label, addedAt}`.
  - `reminders/{YYYY-MM-DD}` `{sentAt, items, count, devices, errors}` (written by the sender only).
- Every page write goes through `data()`. A write is reported as done when issued and only a rejected write shows `"Couldn't save — try again"` (the `saveName` pattern).
- Free text (titles, notes, device labels) is placed with `textContent` only. `innerHTML` is allowed only for the fixed SVG icon table in `main.js`.
- Every new file under `js/`, `css/`, `icons/` or `vendor/` is added to `FILES` in `sw.js` (`js/tests/sw.test.js` enforces this).
- Phone layout: tap targets ≥ 44 px and field text ≥ 16 px (the browser check enforces both). The text box gets `enterkeyhint="done"` and `autocapitalize="sentences"`.
- Exact copy (do not reword):
  - `"e.g. dentist tuesday 2pm"`, `"Nothing on today"`, `"Due soon"`, `"Due"`, `"Skip this one"`, `"Delete"`, `"Just this one"`, `"All"`
  - `"Delete <title>? This can't be undone."`
  - `"Turn on reminders on this device"`, `"Reminders aren't set up yet"`
  - `"On iPhone, add the app to your Home Screen first, then turn reminders on there"`
  - notification titles `"Today"` / `"Today and coming up"`, at most 4 body lines and then `"+N more"`
- Tests never go online. The tools import the Admin SDK lazily, so tests never load it.

## Review Focus

1. **FCM is down at 7am.** If every send fails with a non-dead error, the day must not be marked handled. No `reminders/D` is written, the run exits 1, and the next hourly run tries again. Pinned in Task 8 (`a run where every send fails leaves the day open for the next hour`).
2. **Two runs at once.** The cron-job.org run and GitHub's backup schedule can overlap. The workflow's `concurrency` group serialises them, and the second run sees `reminders/D` and stops. Pinned in Task 8 (`a second run on the same day sends nothing` and the workflow grep in Step 4).
3. **Odd documents in Firestore.** A hand-edited or half-synced event (date `"2026-02-30"`, `repeat.every` 0, no title, `skipped` not an array) is skipped by the page and the sender. It never crashes either one and never expands for ever. Pinned in Task 4 (`eventsFrom skips documents that are not valid events`).
4. **Nonsense in the text box.** `"31/2"`, `"13pm"`, `"at 25"` and `"every 0 weeks"` are never stored as a date, time or repeat. They stay in the title, and Save stays disabled while there is no date. Pinned in Task 2 (`text that is not a date or time stays in the title`).
5. **A long unbroken title.** An 80-character title with no spaces must not widen the page in Coming up, the month day list, the Overview card or the preview. Pinned in Task 9 (seeded and measured at both widths).

### Task 2: Plain-words parser

**Files:**
- Create: `js/calendar/parse.js`
- Modify: `sw.js` (FILES), `js/tests/run-node.mjs`, `tests.html`
- Test: `js/tests/calendar-parse.test.js`

**Interfaces:**
- Consumes: `addDays(day, n)` and `weekdayIndex(day)` (Monday 0) from `js/lessons/sums.js`.
- Produces: `parse(text: string, today: "YYYY-MM-DD") -> { title, kind, date, time, repeat, until, unsure: string[] }`. Fields not found are `null`; `title` is `""` when nothing is left; `unsure` is `[]` or `["date"]`. Also `daysInMonth(year, month1to12) -> n`, `nthWeekdayOf(year, month, weekday0Mon, nth) -> "YYYY-MM-DD"|null` (nth −1 = last), and `MONTH_NAMES`/`WEEKDAY_NAMES` (word → index, accepting full names and 3-letter forms, plus `tues`, `thur`, `thurs`, `sept`).

**Grammar.** Match case-insensitively against the original text. Each match is cut out of the text (its span is replaced with a space), so the title keeps Tom's own casing. Rules run in the order below, and at each step the longest phrase wins. `W` is a weekday word, `M` a month word, `N` digits, `ORD` = `N(st|nd|rd|th)?`, `NTH` = `first|1st|second|2nd|third|3rd|fourth|4th|last`. An optional leading `on ` or `from ` is cut with any date.

| # | Phrase | Result |
|---|---|---|
| 1 | `until <date>` (any date form in 4) | `until` = that date. A date with no year rolls forward to on or after the start date. |
| 2a | `(on )?the NTH W of every month` · `every NTH W( of the month)?` | `repeat {unit:"month", every:1, monthly:"weekday", nth}`; start = the first matching date ≥ today |
| 2b | `every month on the ORD` · `on the ORD of every month` | `{month, 1, "date"}`; start = that day number ≥ today (this month, otherwise the first later month that has the day) |
| 2c | `every other W` | `{week, 2, null}`; start = next W, today excluded |
| 2d | `every W` | `{week, 1, null}`; start = next W, today excluded |
| 2e | `every N (day|week|month|year)s?` with 1 ≤ N ≤ 52 (otherwise no match) | `{unit, N, unit === "month" ? "date" : null}`; start = today |
| 2f | `every other (day|week|month|year)` | as 2e with N = 2 |
| 2g | `every (day|week|month|year)` · `daily` · `weekly` · `fortnightly` (week, 2) · `monthly` · `yearly` · `annually` | as 2e with N = 1 (or 2) |
| 2h | `every ORD M` · `every M ORD` | `{year, 1, null}`; start = next such date ≥ today |
| 2i | `every (spring|summer|autumn|winter)` | `{year, 1, null}`; start = next 1 Mar / 1 Jun / 1 Sep / 1 Dec ≥ today; `unsure: ["date"]` |
| 3 | `due` · `deadline` (each with an optional following `on`, `:` or `-`), and `by` only when a date from row 4 directly follows | `kind: "deadline"`; the word is cut |
| 4 | dates: `today` · `tomorrow` · `in N days?` · `in N weeks?` · `next W` · `W` · `ORD M( YYYY)?` · `M ORD( YYYY)?` · `D/M( /YY| /YYYY)?` · `the ORD` | see below |
| 5 | times: `noon` · `midday` → 12:00; `(at )?H([.:]MM)?\s?(am|pm)` with H 1–12 (12am → 00, 12pm → 12); `at H([.:]MM)?` with H 0–23 → as written; `HH:MM` 0–23 | `time` |

Date rules for row 4. Only the first date found counts; any later dates stay in the title.
- A weekday on its own means the next one, with today excluded.
- `next W` means that weekday in next week (Monday-start), i.e. `addDays(today, 7 - weekdayIndex(today) + W)`.
- `in N days` adds N; `in N weeks` adds 7N.
- A day and month with no year means this year, or next year if it has already passed. Today counts as not passed.
- `D/M` is UK order; `YY` means 20YY.
- `the ORD` means this month if that day ≥ today's day number, otherwise the next month that has that day.
- An impossible date (`31/2`, `30 feb`) or a time out of range (`13pm`, `at 25`, `9:75`) is not a match and stays in the title.

After the rules:
- If both a repeat and a row-4 date are found, the date is the start. If a weekly W repeat disagrees with that date's weekday, add `unsure: ["date"]`.
- `kind` is `deadline` if row 3 matched; otherwise `job` if there is a repeat; otherwise `appointment`.
- `date` is the row-4 date, else the repeat's start, else `null`.
- The title is the leftover text: collapse spaces, trim the connectors `on at the from by every of , - –` from both ends (repeatedly), capitalise the first letter only, and cut to 80 characters.

### Task 3: Occurrences and lesson days

**Files:**

- Modify: `sw.js`, `js/tests/run-node.mjs`, `tests.html`
- Test: `js/tests/calendar-occurrences.test.js`

**Interfaces:**
- Consumes: `daysInMonth`, `nthWeekdayOf` (Task 2); `addDays`, `weekdayIndex` (lessons sums); the lessons records shape `{ days: {[date]: {lessons, note}}, settings: {timetable /* Monday-first, 7 numbers */, trackingSince} | null }`.
- Produces:
  - `occurrences(events, from, to) -> [{ eventId, date, time, title, kind, done }]`. Inclusive range. Skipped dates are dropped. `done` = `event.done.includes(date)`. Sorted by date, then time (all-day `null` first), then title (`localeCompare`).
  - `dueDates(event, from, to) -> string[]`, the expansion below, before skipping.
  - `lessonItems(records, from, to, today) -> [{ date, kind: "lessons", title, time: null, link: "#/lessons" }]`:
    - On days ≤ today, a recorded day with `lessons > 0` gives `"6 lessons"` (`"1 lesson"`).
    - On days ≥ today with no recorded row, a timetable count > 0 gives `"Lessons — usually 6"`, but only from `settings.trackingSince` onwards.
    - No settings means past rows only.

**Expansion** (the one non-obvious algorithm). There is no open-ended loop: every rule jumps straight to the first step that can reach `from`, and stops past `to`/`until`.

```js
export function dueDates(ev, from, to) {
  const S = ev.date, end = ev.until && ev.until < to ? ev.until : to;
  if (!ev.repeat) return S >= from && S <= end ? [S] : [];
  const { unit, every: n } = ev.repeat, out = [];
  const [sy, sm, sd] = S.split("-").map(Number);
  const dayGap = (a, b) => (Date.UTC(...b.split("-").map((x, i) => x - (i === 1))) - Date.UTC(...a.split("-").map((x, i) => x - (i === 1)))) / 864e5;
  if (unit === "day" || unit === "week") {
    const step = unit === "day" ? n : 7 * n;
    let k = Math.max(0, Math.ceil(dayGap(S, from) / step));
    for (let d = addDays(S, k * step); d <= end; d = addDays(S, ++k * step)) out.push(d);
    return out;
  }
  const monthsFrom = (y, m) => (y - sy) * 12 + (m - sm);           // months after the start month
  const [fy, fm] = from.split("-").map(Number);
  const stepMonths = unit === "year" ? 12 * n : n;

      : `${y}-${String(m).padStart(2, "0")}-${String(Math.min(sd, daysInMonth(y, m))).padStart(2, "0")}`;

  }
  return out;
}
```

The title is `"Today and coming up"` when rule 5 gives a line, otherwise `"Today"`. `lines` is the first 4 items, plus `"+N more"` when there are more than 4.

    - `send(message)` resolves `{ ok: true }` or `{ ok: false, error, dead }`.

`runNotify` steps, in order:
1. `await refresh()`; a failure is logged as `::warning::Met Office warnings couldn't be refreshed` and the run carries on.
2. `D = londonDay(now)`, `hour = Number(londonHourStart(now).slice(11, 13))`. If hour < 7, return `early`. If hour ≥ 21, return `late`. If `users/{uid}/reminders/D` exists, return `done-already`. (In a dry run, also skip the window and once-a-day checks when `argv` has `--any-time`.)
3. Read `events`, `lessonDays`, `settings/lessons` and `devices` (docs without a string `token` are ignored), then `buildDigest`.
4. In a dry run, log the title and body, then `dry-run`, with no writes.
5. If `count === 0`, write `reminders/D` = `{ sentAt: now.toISOString(), items: [], count: 0, devices: 0, errors: [] }` and return `nothing`.
6. Send one message per device. A dead result removes `devices/{id}` and adds it to `removed`; any other failure adds `{ device: id, error }` to `errors`.
7. If no device received it and some device failed without being dead, return `failed` with exit code 1 and no record. Otherwise write `reminders/D` = `{ sentAt, items: digest.items, count, devices: <sent count>, errors }` and return `sent`.

`main` behaviour:
- A missing or blank `FIREBASE_SERVICE_ACCOUNT` logs `::notice::FIREBASE_SERVICE_ACCOUNT is not set — reminders were not sent` and returns 0.
